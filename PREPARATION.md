# Kubecost Connector — Preparation

**Category:** C41. Cloud Cost Management (FinOps)  
**Status:** App Preparation Complete (Genuinely Vendor-Specific)  
**Standard:** APP_PREPARATION_STANDARD.md

## 1. Паспорт коннектора
- **Название:** Kubecost Connector (`kubecost-connector`)
- **Официальный портал вендора:** https://kubecost.com
- **Базовый API:** `http://<kubecost-endpoint>:9090/model`
- **Модель аутентификации:** Basic Auth / Bearer Token / Port-forwarding
- **Назначение:** Интеграция платформы Imperal Cloud с Kubecost для автоматизации предметной области: детальный учет расходов на уровне пространств имен (namespaces), подов, сервисов и контроллеров Kubernetes.

## 2. Решаемая проблема
Когда **Kubernetes-администратор** сталкивается с задачей **детальный учет расходов на уровне пространств имен (namespaces), подов, сервисов и контроллеров Kubernetes**, возникает необходимость ручного мониторинга, дублирования статусов и переключения между окнами. Это приводит к потере времени, замедлению реакции на инциденты и ошибкам ручного ввода.

## 3. Роли и права доступа
- **Kubernetes-администратор, Platform Engineer**
- Принцип наименьших привилегий (Least Privilege): токен запрашивает доступ только к разрешенным операциям чтения и подтвержденным действиям.

## 4. Ключевые сущности
распределение затрат (/allocation), утилизация ресурсов (/assets), рекомендации (/recommendations)

## 5. Первичный рабочий сценарий
`запрос распределения затрат по неймспейсам за неделю -> выявление перерасхода CPU/Memory -> аудит квот`.

## 6. Границы коннектора
- Изолированное хранение секретов (BYOC).
- Никаких фиктивных методов сторонних предметных областей.
- Деструктивные операции требуют явного подтверждения пользователя.
